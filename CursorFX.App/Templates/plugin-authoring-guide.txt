Fluxor Plugin Authoring Guide
=============================

1. Core idea
------------
Fluxor now uses a DLL-only plugin flow.

You ship one compiled plugin DLL.
The DLL contains:
- rendering logic
- plugin identity
- parameter schema for the UI
- default values and section grouping

Fluxor reads all of this directly from the plugin type.
Separate JSON manifests are no longer required for import.
The recommended workspace layout is one plugin project per folder inside the shared Plugins directory.


2. What the plugin must implement
---------------------------------

Your plugin class must:
- implement ICursorEffectPlugin
- have a public parameterless constructor
- expose metadata and settings schema from code

Minimal required namespace:

using CursorFX.Core.Interfaces;

Common additional namespaces:
- using System;
- using System.Collections.Generic;
- using System.Windows;
- using System.Windows.Media;
- using CursorFX.Core.Models;


3. Required runtime contract
----------------------------

Your class should expose:
- DisplayName
- PluginId
- Description
- IconGlyph
- AccentColor
- Kind
- Trigger
- GetParameters()

And implement:
- ApplyParameters(IReadOnlyDictionary<string, TemplateParameterValue> parameters, double masterOpacity)
- Update(TimeSpan deltaTime)
- Render(DrawingContext drawingContext)
- OnMouseMove(Point position)
- OnMouseClick(Point position)
- Dispose()


4. Minimal skeleton
-------------------

using System;
using System.Collections.Generic;
using System.Windows;
using System.Windows.Media;
using CursorFX.Core.Interfaces;
using CursorFX.Core.Models;

namespace MyCompany.FluxorPlugins;

public sealed class MyPlugin : ICursorEffectPlugin
{
    public string DisplayName => "My Plugin";
    public string PluginId => "my-plugin";
    public string Description => "My custom effect.";
    public string IconGlyph => "M";
    public string AccentColor => "#4FD1C5";
    public TemplateEffectKind Kind => TemplateEffectKind.CursorAura;
    public TemplateTrigger Trigger => TemplateTrigger.FollowCursor;

    public IReadOnlyList<TemplateParameterDefinition> GetParameters() =>
    [
        new TemplateParameterDefinition
        {
            Key = "opacity",
            DisplayName = "Opacity",
            Section = PluginParameterSection.Shader,
            SectionName = "Shader",
            Type = TemplateParameterType.Number,
            Min = 0.05,
            Max = 1.0,
            Step = 0.01,
            DefaultNumber = 0.8
        }
    ];

    public void ApplyParameters(IReadOnlyDictionary<string, TemplateParameterValue> parameters, double masterOpacity)
    {
    }

    public void Update(TimeSpan deltaTime)
    {
    }

    public void Render(DrawingContext drawingContext)
    {
    }

    public void OnMouseMove(Point position)
    {
    }

    public void OnMouseClick(Point position)
    {
    }

    public void Dispose()
    {
    }
}


5. How Fluxor builds the settings UI
------------------------------------

Fluxor uses GetParameters() to build the settings panel.

Each parameter must define:
- Key
- DisplayName
- Section
- SectionName
- Type
- Min
- Max
- Step
- DefaultNumber or DefaultColor or DefaultBoolean

Type values:
- Number
- Color
- Toggle

Sections:
- Trail
- Glow
- Ripple
- Shader


6. Mapping rules inside the plugin
----------------------------------

If your plugin reads:
- opacity
- primaryColor
- enabled

then these exact keys must exist in GetParameters().

Example:
- GetNumber("opacity", 0.8) -> Number parameter with Key = "opacity"
- GetColor("primaryColor", "#7DD3FC") -> Color parameter with Key = "primaryColor"
- GetToggle("enabled", true) -> Toggle parameter with Key = "enabled"

Key names must stay stable.
Changing them later will reset user settings for that plugin.


7. Recommended plugin structure
-------------------------------

Use this layout:
- configuration fields
- runtime state
- cached visual resources
- metadata properties
- GetParameters()
- ApplyParameters(...)
- Update(...)
- Render(...)
- OnMouseMove(...)
- OnMouseClick(...)
- Dispose()

Best practice:
- read and clamp values in ApplyParameters
- rebuild cached resources only when values change
- keep Update for animation only
- keep Render focused on drawing only


8. Performance recommendations
------------------------------

- Use fixed-size buffers for trails and particles
- Reuse lists and arrays where possible
- Avoid creating Random every frame
- Avoid rebuilding Pen and Brush objects inside Render
- Clamp deltaTime
- Cap maximum spawned elements
- Prefer one well-shaped shader/ribbon over many weak particles
- Keep external screen sampling optional and minimal

For plugin DLLs specifically:
- keep per-frame allocations low
- avoid creating large geometries for tiny details
- avoid reflection or file IO during render/update
- cache parsed colors and derived values after ApplyParameters


9. Stability recommendations
----------------------------

- Always provide safe defaults
- Never assume a parameter exists
- Clamp all numeric values
- Keep Dispose lightweight
- Fail gracefully if a parameter is missing
- Keep one plugin self-contained
- Do not depend on another plugin DLL being loaded first


10. Visual design recommendations
---------------------------------

Cursor effect design works best when:
- cursor is the source, not the whole effect
- the effect can live briefly after the cursor moves on
- one strong silhouette leads the look
- secondary details support the silhouette instead of replacing it

Examples:
- electric: smooth emitter + branching arcs + calm idle corona
- fireflies: few readable lights + short curved micro-trails
- void: dark ribbon mass + subtle inner glow + slow healing tail
- aurora: one connected soft band + inner light core


11. Import workflow
-------------------

1. Build the plugin DLL inside its own folder under Plugins
2. In Fluxor click Import Plugin
3. Choose the DLL
4. Optionally choose an icon image
5. Confirm import

Fluxor will:
- load the plugin type
- read metadata from the DLL
- build the profile automatically
- copy the DLL and its companion runtime files into the plugin catalog


12. Where to create and store plugins
-------------------------------------

Recommended workspace:
- `C:\Users\Gyrocopter_UA\Desktop\TestProj\Plugins`

Recommended layout:
- one folder per plugin
- one `.csproj` per folder
- one main plugin class per folder

Examples already included:
- `Plugins\Fluxor.PluginCursorFlameContour`
- `Plugins\Fluxor.PluginVelvetVoid`
- `Plugins\Fluxor.PluginFireflySwarm`

Recommended user flow:
1. Copy one of the sample folders
2. Rename the folder and project
3. Change:
   - namespace
   - class name
   - DisplayName
   - PluginId
4. Build the project
5. Import the DLL into Fluxor


13. How to build the DLL
------------------------

From the project root:

`dotnet build .\Plugins\MyPluginFolder\MyPluginProject.csproj -m:1 -v minimal`

Example:

`dotnet build .\Plugins\Fluxor.PluginVelvetVoid\Fluxor.PluginVelvetVoid.csproj -m:1 -v minimal`

The built DLL will be here:

`Plugins\MyPluginFolder\bin\Debug\net9.0-windows\MyPluginProject.dll`

Fluxor imports this DLL file directly.


14. How to install the plugin into Fluxor
-----------------------------------------

1. Open Fluxor
2. Click `Import Plugin`
3. The dialog opens in the shared `Plugins` folder by default
4. Choose your built DLL
5. If the DLL contains one plugin type, Fluxor selects it automatically
6. If the DLL contains multiple plugin types, choose one in the `Plugin Type` field
7. Optionally choose a custom card icon
8. Confirm import

Fluxor then copies the DLL into its runtime plugin catalog automatically.


15. Recommended testing checklist
---------------------------------

Before sharing a plugin, verify:
- plugin appears in the profile list
- parameters appear correctly in sections
- sliders update live
- colors update live
- effect survives rapid cursor movement
- effect survives repeated clicks
- plugin does not freeze when hidden and shown again
- plugin does not over-allocate on long sessions


16. Common mistakes
-------------------

- not implementing ICursorEffectPlugin
- missing public parameterless constructor
- GetParameters() returns empty list
- key mismatch between parameter schema and code
- rebuilding heavy resources every frame
- creating too many particles for a soft effect
- trying to express every effect as noise instead of one readable shape


17. Best practice for maintainability
------------------------------------

- Keep one clear visual idea per plugin
- Keep one plugin project per folder
- Prefer 8 to 15 meaningful controls
- Name keys in plain English
- Keep PluginId stable
- Keep metadata in code close to the rendering logic
- Use DLL-only import as the canonical Fluxor plugin workflow
